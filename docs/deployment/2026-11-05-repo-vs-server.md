# 仓库项目 ↔ 服务器部署：对应关系（2026-11-05）

> 问题：服务器部署我们的提交后，是不是就和私有仓库项目一样了？
> 答案：**代码和可复现资产一致；但“项目”还包含环境、数据、前端产物，这些属于部署状态，不在仓库里。**

## 1. 项目由哪些部分组成

| 组成 | 私有仓库里有没有 | 服务器上是什么 | 部署后是否一致 |
|---|---|---|---|
| 后端源码（`apps/local-api`） | ✅ 有 | 镜像/容器，来自某个 commit | ✅ 部署同一 commit 即一致 |
| 契约与共享包（`packages/*`） | ✅ 有 | 同上（打进后端镜像） | ✅ |
| 前端源码（`apps/web`） | ✅ 有 | **不是**从仓库直接构建的线上产物 | ⚠️ 见 §2 |
| 前端运行产物（release 目录） | ❌ 仓库不存产物 | `releases/<tag>/web` | ⚠️ 单独发布 |
| 运行时环境变量（`env.list`） | ❌ 含凭据，不进仓库 | `/opt/vivic-preview-20261025/backend/env.list` | 需单独同步（模板见 `tooling/release/README.md`） |
| 数据（SQLite / 资产） | ❌ 不进仓库 | `/var/lib/vivic-preview-20261025` | 不回写仓库 |
| nginx / TLS / 域名 | ❌ | 宿主机配置与证书 | 不回写仓库 |
| 部署脚本（服务器侧 `deploy.sh`/`rollback.sh`） | ❌ | 服务器 `/opt/.../backend/` | 仓库只有 v2 方案（`tooling/release/`） |
| 验收套件 / 数据集 / 汇报 | ✅ 现在有（`tooling/`） | 不部署（本机跑） | — |
| 决策记录 / 审计 / 对账表 | ✅ 有（`docs/decisions`、`docs/audits`） | 不部署 | — |

## 2. 前端为什么不能简单“仓库构建 = 线上”

线上 UI 是**构建产物 + 逐 release 补丁**，其私有源树只能重建出部分 chunk（见 `tooling/reports/01-...` §1）。所以线上前端 release 是独立发布物：

- 仓库里的 `apps/web` 是源码基线；
- 线上 `sections-20261103-final` 是在产物上打 sections 兼容补丁后的 release；
- 前端更新走单独发布，不受后端 commit 影响。

**结论**：后端“部署 86 个提交”只会让**后端**与仓库一致；前端仍是它自己那条发布线。

## 4. 要让“两边一样”，部署时必须做的事

1. **记录 commit**：部署的 sha 写进 `DEPLOYED`（服务器已有此机制）；
2. **环境变量先对比**：把 `env.list` 与 `tooling/release/README.md` 的变量表逐项核对，改前备份；
3. **数据先备份**：部署脚本已自动备份 SQLite；
4. **前端单独发**：后端部署不改变前端 release；
5. **部署后跑 60 条**：与本地对比，结果写进汇报；
6. **保留回滚点**：上一版镜像/目录 + 数据备份。
