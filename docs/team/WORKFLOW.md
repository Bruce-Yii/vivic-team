# Vivic 协作任务与 Agent 执行流程

> 本文是可复用的任务执行模板。它不绑定任何人的 GitHub 账号，也不假设后续协作发生在原始仓库。
> **唯一实际工作区是协作者复刻后的仓库。** 开工前先读 [前端源码留存与协作仓库版本同步规范](FRONTEND_SOURCE_AND_VERSION_SYNC.md)，确认协作者仓库 owner/name、默认分支和访问权限。

## 1. 任务如何进入开发

一项需求先明确用户结果，再拆成可独立交付的任务。每项任务应包含：

- Goal：最终要让使用者获得什么；
- Scope / Non-scope：允许改什么、明确不改什么；
- Baseline：协作者仓库、默认分支、基线 commit SHA；
- Owner：一个主要执行负责人；
- Dependencies：前置接口、文件、其他任务；
- Acceptance：可观察、可复现的验收条件；
- Risks：最可能的误解、兼容性风险和禁止操作。

任务可以记录在协作者仓库的 GitHub Issue、项目看板或团队已有任务系统中；采用哪种工具由协作者仓库所有者决定。无论工具是什么，任务记录都必须指向实际协作者仓库中的代码和 commit。

## 2. Agent 开工前检查

开工前必须先确认：

1. 当前仓库完整名称是否为协作者仓库；
2. `origin` 是否指向该协作者仓库；
3. 默认分支名称和最新 HEAD SHA；
4. 当前工作区是否有未提交改动；
5. 任务是否已经存在，是否与其他任务重复或冲突；
6. 本任务允许修改的文件、接口和依赖范围。

不要把 `Bruce-Yii/vivic-team` 当作默认开发目标。它是原始来源；只有用户明确要求时才向原始仓库贡献。

## 3. Git 与多人协作

- 所有人从同一个协作者仓库 clone；每个 Agent 使用独立 worktree / 工作目录和独立任务分支。
- `origin` 指向协作者仓库。若它是 GitHub Fork，可选设置只读用途的 `upstream` 指向原始仓库；若是独立复制，则无需配置来源 remote。
- 新任务从协作者仓库最新默认分支创建分支；不要硬编码 `main`，以仓库实际默认分支为准。
- 本地未提交的改动不会同步给其他人；commit 但未 push 也不会同步到其他设备。需要交接时先 push，再给出仓库、分支和 SHA。
- 不同 Agent 不得在同一个工作目录里同时切分支或覆盖同一批文件。
- 协作者仓库默认分支更新后，任务分支应先保存自身改动，再 fetch 并同步最新基线，解决冲突后重新验证。
- 不得无条件 merge 原始仓库的 `main`；如需取回来源更新，先 compare 差异，选择明确需要的提交或文件。

## 4. 代码范围与接口协作

- 先做任务需要的最小改动，不顺手重构其他模块。
- 共享 API / 数据契约变更先定义字段、类型、必填性、默认值、错误形状和兼容策略，再分别实现前后端。
- 优先向后兼容；涉及破坏性变更时拆成迁移步骤，不让新前端依赖尚未提供的后端接口。
- 当前优先后端协作。后端任务未明确涉及前端时，不改 Web 页面、不重打前端包、不升级前端依赖。
- 前端修改必须落在可编辑源码中，不能只在服务器上编辑压缩 bundle；构建产物必须能追溯到源码 SHA。
- Mock、fixture 和 Demo 数据必须明确标记，不能冒充真实服务结果。

## 5. 提交与交接

任务完成后，执行者必须提供：

- 实际协作者仓库 owner/name；
- 分支名、基线 SHA、当前 HEAD SHA；
- 修改文件和每项改动的目的；
- 已执行的测试/构建命令及真实结果；
- 未执行、失败或无法验证的项目；
- 兼容性、部署依赖、回滚注意事项；
- 若使用 PR，提供协作者仓库内的 PR 链接和目标分支。

只有在用户或协作仓库维护者明确授权后，才执行 push、创建 PR、合并或部署。不要把本地完成描述成远端已交付；不要把旧 SHA 的验证结果套用到新提交。

## 6. 给 Agent 的开工提示词

```text
你负责协作者仓库中的任务【任务名称 / Issue 链接】。
先确认仓库 owner/name、origin、默认分支、最新基线 SHA 和工作区状态。原始仓库 Bruce-Yii/vivic-team 只作为来源参考，不是默认开发目标。
先核对现有任务和相关代码，写清 Goal、Scope、Non-scope、允许修改的文件、接口、依赖、风险和验收标准。
当前优先后端；任务未明确涉及前端时，不修改 Web 页面、不重打前端包。涉及 API 时先对齐共享契约并写清向后兼容策略。
使用独立 worktree 和任务分支；不要覆盖其他 Agent 的文件或未提交改动。
结束时报告协作者仓库、分支、基线 SHA、HEAD SHA、修改文件、实际验证结果、未验证项和下一步。
未经明确授权，不 push、不创建 PR、不合并、不部署。
```

## 7. 给 Agent 的提交提示词

```text
请基于当前任务完成结果准备远端交付。
先检查实际协作者仓库、完整 diff、工作区、当前分支和 HEAD SHA；只包含本任务允许的文件。
执行与改动相关的验证，并如实记录命令、环境、结果和失败项。
只有在用户或仓库维护者已明确授权时，才 push 到协作者仓库并创建/更新 PR。
PR 的 base 必须是协作者仓库自己的默认分支，不得默认指向 Bruce-Yii/vivic-team:main。
不要自动合并、启用自动合并、部署、强推或修改仓库设置。
最后回传协作者仓库、PR 链接、head SHA、改动范围、验证证据和未完成事项。
```
